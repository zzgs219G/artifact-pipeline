## 2. 模块清单与依赖

| 模块 | 参数 | 产物特征 | 依赖 |
|---|---|---|---|
| 签名校验 | `--sigcheck` | `lib/*/libnc.so` | 需 NDK |
| dex2c 转译 | `--dex2c [规则]` | `libnc.so` 内的 `Java_*` 符号 | 依赖 sigcheck 或规则文件 |
| 字符串加密 | `--stringenc <规则>` | 业务 dex 里的解密桩 | 规则必填 |
| ↳ 联动子项 | `--dex2c-stub` | 桩搬进壳 dex + 4 方法 native 化 | **必须同时勾 dex2c + stringenc + packer** |
| 防对比 | `--anti-diff` | 无独立产物（改 smali 结构） | — |
| 环境检测 | `--envcheck` | 并入 `libnc.so` | 需 NDK |
| 基础加壳 | `--packer` | `assets/xixin/*` + Manifest 改 Proxy* | **必须最后跑** |

**固定执行顺序**：`sigcheck → dex2c → stringenc → anti-diff → envcheck → packer`
（由 `protect.sh` 硬编码，与勾选顺序无关）

**模块化红线**：不勾某模块时，其行为必须与"该模块从未存在"逐字节一致。
新增参数一律"不传 = 零行为变更"。

## 3. 拿到产物先判断组合

**不能跳过。** 不同组合的故障定位路径完全不同，但症状可能都是"装上去崩了"。

```bash
scripts/verify/identify-combo.sh <apk>
```

### 3.1 四类组合

| 组合 | 壳 so | `libnc.so` | stringenc 桩 | 是壳包？ |
|---|---|---|---|---|
| 只勾 packer | ✅ | ❌ | ❌ | ✅ |
| **全模块（含 packer）** | ✅ | ✅ | ✅ | ✅ |
| **全模块但不勾 packer** | ❌ | ✅ | ✅ | ❌ |
| 未加壳原包 | ❌ | ❌ | ❌ | ❌ |

### 3.2 第三类最容易误判

「全模块但不勾 packer」看起来"什么都有"（有 `libnc.so`、有解密桩），
但它**不是壳包**：

- 没有 `.bitcode` / `xixin_config` / `xixin_data`
- 业务 dex 未被抽取
- Manifest 不改 `ProxyApplication`
- 启动时**不会**有 `[kl]` 日志

**后果**：拿它跑 `verify-on-device.sh` 会判「派生链失败」——
**那是假阳性**。该类产物的测试重点是"桩能否正常解字符串"（纯 Java，
不依赖 so），与壳无关。

### 3.3 判据实现注意

```bash
# ❌ 错：grep -q 命中即退出 → SIGPIPE 杀掉 unzip → 整条管道判失败
unzip -l app.apk | grep -q 'assets/xixin/.*/libxixin\.so'

# ✅ 对：先落文件
unzip -l app.apk > /tmp/list.txt
grep -qE 'assets/xixin/[^/]+/libxixin[.]so' /tmp/list.txt
```

**stringenc 桩不能靠类名判断**：桩类名每包随机（防固定签名），
实测全模块产物 `grep -c strdec` = **0**。必须用桩骨架的结构不变量
`GAMMA` / `keyByte` / `mix64`（这三个名字不参与随机化）。

## 4. 验证

### 4.1 静态（不需要设备）

上游 dpt-shell 自带段级核验（在 `../dpt-shell/scripts/dev/verify-apk-static.sh`）：
`.bitcode` 熵、`DPT_UNKNOWN_DATA` 是否移除、`.comment`、派生常量明文、
载荷块自洽。**改了 dpt 之后跑它**。

### 4.2 真机（需要设备）

```bash
scripts/verify/verify-on-device.sh <apk> --device <host:port>
```

判据（任一失败即 FAIL）：

| 判据 | 含义 |
|---|---|
| `[kl] ... derive_rc=0` | 派生链成功 |
| 无 `config:` 错误 | 配置链成功 |
| 无 `materializeBlock` 失败 | 载荷链成功 |
| 无 `java_class == null` | JNI 注册成功 |
| 进程存活 | 最终判据 |

**前置检查**：非壳包直接 `exit 2` 并提示先跑 `identify-combo.sh`，
不产假阳性。

### 4.3 该测哪些组合

**至少两个**，任一失败都算未通过：

1. **只勾 packer** —— 验证 dpt 自身三条链。**定位最快**：
   v1.2.6~v1.3.1 的所有 dpt 缺陷在这个组合下都能复现
2. **全模块**（`sigcheck + dex2c + stringenc + dex2c_stub + envcheck + packer`）
   —— 验证联动：桩进壳 dex、`gseed`、dex2c 产物与壳协同

## 5. 代码地图

| 路径 | 职责 |
|---|---|
| `scripts/pipelines/protect.sh` | **唯一加固总控**。勾选解析 → 固定顺序 → 输出 |
| `scripts/packer/packer.sh` | 解压 dpt 工具包并调用 `dpt.jar`（契约见其文件头注释） |
| `scripts/string-enc/encrypt-strings.py` | 字符串加密 + 解密桩注入 + `--emit-stub-dex` |
| `scripts/filter/rules-to-filter.py` | 用户规则（点号通配）→ dcc filter（斜杠正则） |
| `scripts/lib/lib-ndk.sh` | NDK 工程生成（`Android.mk` / version script） |
| `scripts/verify/` | **验证脚本**：`identify-combo.sh` + `verify-on-device.sh` |
| `tools/dpt-shell.zip` | 上游工具包（换版 = 整包替换 + 改 `工具包版本.md`） |
| `configs/v1/config-schema.json` | App 勾选 UI 的 schema（加模块只改这一份） |

**规则语义警告**（常见踩坑）：
`dex2c` / `stringenc` 里 `!com.x.**` = **排除**；`dpt -r` 里命中 = **不加固**。
方向相反，且语法一个是点号通配、一个是斜杠正则。**不可共用一份规则。**

## 6. 换版流程（dpt-shell 升级）

1. 上游打 tag 并等 CI 绿
2. 下载 release zip，核验 sha256
3. `cp` 替换 `tools/dpt-shell.zip`
4. **删除 `tools/executable/`**（`ensure_dpt` 靠"jar 存在"判断幂等，
   旧解压产物在会静默用旧版）
5. 改 `tools/工具包版本.md` 一行（版本 / sha256 / build-key / seed）
6. 跑 `scripts/packer/tests/test-packer.sh` 与 `test-protect-packer-wiring.sh`

**必须核对的三处契约**（查上游源码，不反编译）：
CLI 选项 → `../dpt-shell/dpt/src/main/java/com/luoye/dpt/config/Const.java`；
产物命名 → `AndroidPackage.buildPackage`；
解压布局 → `getExecutablePath()` + `shell/build.gradle`。
