## 二、今天修的两个严重 bug（都有真机证据）

### Bug 1：`.a` 分发包漏了 `nc_guard_jni.c`

**现象**：加固包启动即闪退

```
No implementation found for com.nc.link.NcLink.selftest()
→ UnsatisfiedLinkError → Guard 判定"so 缺失" → signal 9
```

**根因**：`make-zip-lib.sh` 的 `LIB_SRCS` 只有 4 个 `.c`，漏 `nc_guard_jni`。

**修复**：`nox` 提交 `1f1a732`。**这是「承重墙」设计在正常工作**
（so 缺失必须死不能静默），问题在分发件缺件。

### Bug 2：桩被无条件 native 化（更严重）

**现象**：全模块构建**全绿**，装上去启动即闪退

```
No implementation found for <随机桩名>.md()
at com.xixin.box.xiApplication.<clinit>
```

**触发条件**：`dex2c` + `stringenc` + `packer`，**不勾** `--dex2c-stub`

**根因链**：

```
emit_stub_dex 无条件把桩的 4 个方法改成 native（target_names 硬编码）
  ↓
但不勾 --dex2c-stub 时 dex2c 从没转译桩 → libnc.so 里没有实现
  ↓
Application.<clinit> 的加密字符串调 md() → ULE
```

**修复**：新增 `_stub_transpiled()`，按类描述符查 `compiled_methods.txt`：

| 桩在 compiled_methods | 行为 |
|---|---|
| 在（勾了 `--dex2c-stub`） | native 化 + 插 `loadLibrary("nc")` |
| 不在（未勾联动） | **保持明文 Java**，不需要 so |

**顺带修的**：`loadLibrary("nc")` 原来绑在 `--stub-seed-from-shell` 上
（可选特性），现在只要 native 化就**无条件**插进桩自己的 `<clinit>`。

> **为什么插桩 `<clinit>` 而不是宿主 `Application.<clinit>`**：
> JVM 规范保证「类的静态方法被调用前必须先完成该类初始化」，
> 所以任何调 `md()` 的地方都受保护，不依赖宿主类形态。

## 八、遇到闪退的排查速查

```bash
adb logcat -c
adb install -r <apk>
adb shell monkey -p com.xixin.box -c android.intent.category.LAUNCHER 1
sleep 10
adb shell pidof com.xixin.box        # 无输出 = 已退出
adb logcat -d | grep -iE "FATAL|UnsatisfiedLink|No implementation|ncguard|selftest"
```

| 现象 | 根因 |
|---|---|
| `No implementation for <桩>.md()` | 桩被 native 化但 so 无实现（Bug 2） |
| `No implementation for NcLink.selftest()` | `.a` 缺 `nc_guard_jni`（Bug 1） |
| signal 9 无 FATAL | Guard 的 fail-closed 杀进程（so 缺失/证书不符） |
| `selftest` 返回 `-12` | 证书或包名 fail-closed（keystore 与上传 APK 不同源） |
| `selftest` 返回 `-11` | MAC 校验失败（密文被改） |
