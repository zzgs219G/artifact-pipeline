# 怎么出调试包（带 so 自检报告）

> **一句话**：平时构建不带自检报告；要看报告就加 `DEBUG_REPORT=1`。
> 报告能告诉你「锁箱有没有解开、VMP 有没有生效、每段多大」，不用反汇编。

---

## 1. 平时构建（默认，无报告）

```bash
python3 scripts/trigger_build.py app.apk --sigcheck --vmp --sign
```

**产物里没有报告代码** —— `strings libnc.so | grep -i xixin` 搜不到，
`getenv("NCG_REPORT_PATH")` 也不存在。

> 为什么要这样：外部 0 信息逆向报告实测，逆向者用 Unicorn 仿真
> hook `getenv`/`access`，**5 秒**就发现这两个字符串（`.rodata` 明文），
> `touch` 一下就能让壳吐出 12 步解密流水线，等于把「逆向 12 个未知
> 函数」降级成「读一份自述文档」。
>
> 当时标 ★★★，是那份报告里最严重的两个弱点。

---

## 2. 调试构建（带报告）

```bash
python3 scripts/trigger_build.py app.apk --sigcheck --vmp --sign --debug-report
```

> ⚠️ **`--debug-report` 是 workflow input，必须走 `/api/build` 下单。**
> 早先文档写的是 `DEBUG_REPORT=1 python3 ...` —— 那是**错的**：
> `DEBUG_REPORT` 只是 `lib-ndk.sh` 读的环境变量，本地 shell 设了也
> 传不到 GitHub runner（`trigger_build.py` 不认识它、workflow 也没那个
> input）。2026-11-22 补了 `debug_report` input 打通全链。

构建日志里会多一行确认：

```
[mk] ⚠️ DEBUG_REPORT=1：已编入自检报告（产物不可分发）
```

---

## 3. 装机后怎么看报告

### 3.1 必须有签名一致的包

报告功能自己不校验签名，但 **so 的锁箱密钥由 APK 证书派生** ——
换证书重签会 `rc=-12` 解锁失败。所以调试包必须用**输入 APK 同一张证书**签。

### 3.2 打开报告开关（二选一）

**方式 A：哨兵文件**（推荐，简单）

```bash
adb shell 'touch /storage/emulated/0/xixin_debug'
```

**方式 B：环境变量**（只在能设环境变量的场景可用，如宿主仿真）

```bash
NCG_REPORT_PATH=/tmp/report.md
```

> ⚠️ 方式 B 在真机上普通 App 设不了（Android 不允许为用户进程注入环境变量），
> 只有 root / frida / 仿真环境能用。**真机排障请用方式 A。**

### 3.3 读报告

```bash
adb shell 'cat /storage/emulated/0/Android/data/<包名>/files/ncguard_log.md'
```

例（简盒）：

```bash
adb shell 'cat /storage/emulated/0/Android/data/com.xixin.box/files/ncguard_log.md'
```

## 4. 报告长什么样 / 怎么看

```
**解锁**：✅ 4 段全部解密

| 段名 | 大小 | 权限 | 熵(文件) | 熵(内存) | VMP | 判定 |
| `.ncx`  | 22.9 KB | r-x | 8.093 | 6.890 | - | ✅ 已解密 |
| `.ncxr` |   104 B | r-- | 6.440 | 5.768 | - | 🔒 密文（小段）|
...
**套数**：2
| 1. nox解密链 | `.ncr` 142532 B | `.ncq` ✅ | `.ncs` ✅ |
| 2. 消费方   | `.nct`  48412 B | `.ncv` ✅ | `.ncw` ✅ |
```

**关键判据**：

| 看什么 | 正常值 | 异常含义 |
|---|---|---|
| `**解锁**` | `✅ N 段全部解密` | 报错 = 锁箱没解开，业务代码会 SIGILL |
| 熵(文件) | 加密段 ≈ 8.0 | 接近 6.x = 没加密 |
| 熵(内存) | 加密段 ≈ 6.x | 仍 8.0 = 没解密 |
| `**套数**` | `2` | `1` = 消费方 VMP 没生成 |

**熵的含义**：8.0 = 完全随机（密文，zlib 压不动）；6.x = 有结构（明文）。
**文件密 + 内存明 = 锁箱生效**。

## 5. 报告不含什么（安全边界）

| 不含 | 为什么 |
|---|---|
| 密钥、密钥片段 | 只打段名/大小/权限/熵/判定 |
| 明文内容 | 同上 |
| 算法名 | 中文文案全部密文化（LSGS 机制） |

**它只泄露「做了什么」，不泄露「怎么做」和「用什么做的」。**

---

## 6. 调试包不能发给用户

原因：它有调试开关（哨兵文件 / 环境变量）。

| | 正式包 | 调试包 |
|---|---|---|
| 强度 | 完整 | **相同**（只多一个报告模块）|
| 调试开关 | 无（代码不存在）| 有 |
| 可分发 | ✅ | ❌ |

> 只差一个报告模块，所以**功能问题可以在调试包上复现和排查**。

## 7. 实现细节（改代码的人看）

**编译期开关**：`-DNCGUARD_DEBUG_REPORT`

- 定义 → `nc_guard_report.c` 的 `ncg_debug_log_path()` 参与编译
- 不定义 → 该函数退化为 `return -1`，**整段代码不生成**

**接线位置**：

| 文件 | 干什么 |
|---|---|
| `scripts/lib/lib-ndk.sh` | 读 `DEBUG_REPORT` 环境变量，决定是否往 `Application.mk` 追加 `-DNCGUARD_DEBUG_REPORT` |
| `../nox/scripts/so-guard/nc_guard_report.c` | 用 `#ifdef NCGUARD_DEBUG_REPORT` 包住报告逻辑 |
| `../nox/test.sh` | `guard_compile()` 源码形态固定加该宏（V12 测试依赖报告）|

**为什么用编译期而不是运行期开关**：

- 运行期开关（环境变量/哨兵）→ 字符串进 `.rodata` → `strings` 可见
- 编译期开关 → release 里**代码不存在** → 什么都搜不到

**为什么不用 Android 的 `debuggable`**：

`protect.sh` 已强制 `debuggable=false`。那是安全要求 —— `debuggable=true`
会让 `run-as` 进应用沙箱、调试器直接 attach，绕过反调试探针。
不能为了调试把它改回去。
