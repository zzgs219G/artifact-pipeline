## 2. 方案四：参数语义整理（用户指导：看得懂）

### 用户已理解的命名（必须保留兼容）
- `nox-obf`（或 tag 名 `-obf`）= **nox 层混淆**（libnox.a 打包时烧死：VMP + MBA）——用户记得住这个是"锁箱+VMP"；
- `vmp`（`--vmp`）= **消费方层 VMP**（protect.sh 对 sig_check/guard2 判定点的 Amice 虚拟化）。

### 设计（我的决策，写在这里防压缩后走样）
1. **不动 schema 的勾选模型**（自由选配是用户明确要的），只在**输出侧**加"防护清单"，让每个包自己带说明书：
   - `trigger_build.py` 构建完成后打印一张表：锁箱✅/nox-VMP✅/消费方-VMP✅或❌/两线校验✅/报告✅，并写进 `ncguard_log.md`（装机后手机上可看）。
2. **参数 help 文案改成用户语言**（这是"看得懂"的落点）：
   - `--vmp`：`【强度】消费方层 VMP：把签名校验的判定逻辑虚拟化（默认不开，开了 so 大 200KB+）`
   - `--sigcheck`：已有
   - 在 `trigger_build.py --help` 顶部加一段"两层防护说明"（锁箱=nox 层自动，VMP=两个独立层，tag/参数各管一个）。
3. **文档一页化**：`docs/参数说明.md`（新）——把当前所有参数按"模块勾选 / 强度子项 / 调试开关"三组列成表，每行写"开了会怎样、体积代价、真实效果（引用 §3.5 结论：混淆对仿真无效）"。README 的快速上手段落改指向它。
4. **不做固定档位**（避开用户提的冲突）——只做"预设起点"：trigger_build 的 `--guard-max` 之类作为**预填多个勾选的快捷方式**（等价于 `--sigcheck --envcheck --vmp --stringenc '**'`，可再覆写），help 里明写"这是快捷预填，不是互斥档位"。

### 验收
- `python3 scripts/trigger_build.py --help` 输出里，两层 VMP 的语义用户能一眼分清；
- 出一次包（云端），构建输出里出现防护清单表；`ncguard_log.md` 里也有；
- 本地回归全绿 + push。
