## 1. 为什么需要独立的一条线

| | 加固 | 去校验 |
|---|---|---|
| 方向 | 加防御 | 拆防御 |
| 依赖 | NDK / Amice / nox | 只要 JDK |
| 耗时 | 几分钟 | 几秒 |
| 卡片 | `configs/v1`（7 个模块） | `configs/v2`（1 个开关） |

**刻意不合并**：
1. 合并后「勾 sigcheck（加校验）同时又勾 uncheck（去校验）」是个无法给出合理语义的配置
2. 去校验一个 NDK 都用不上，合并等于让小事付大代价
3. 失败面必须隔离

## 2. 实现要点（改代码前必读）

### 2.1 载荷分两个 dex，不能合并

```
boot.dex      SigFix + SigFixApp  → 进目标 App 的 classes{N+1}.dex
payload.dex   SigFixImpl           → 进 assets，运行时 new DexFile(path) 加载
```

`SigFixImpl` 必须由 **BootClassLoader** 加载才能反射访问 hidden API。
编进 App 自己的 dex → 应用域 → 反射被拦（实测 Android 17：
`setHiddenApiExemptions` 直接 `blocked`，报 `NoSuchMethodException`）。

### 2.2 AXML 改写的两条红线

| 红线 | 为什么 |
|---|---|
| 属性按 **resourceId 升序**插入，不能追加末尾 | `PackageParser` 按资源 ID 升序读 `<application>`，遇乱序提前停止扫描。`android:name` 的 ID 是 `0x01010003`（最小）→ 插最前 |
| `rawValue` 必须是**字符串池索引**，不是 `NO_INDEX` | `raw` 与 `typedValue.data` 都要填索引且相同；写 `NO_INDEX` 时值读不出 |

**症状统一**：系统读不到 `android:name`、App 照旧跑原类、**零报错**。

**验证必须三层**（缺一层就可能踩坑 39）：

```bash
# 1) 自己的解析器读回（最弱，只能发现读写不一致）
python3 scripts/uncheck/axml_edit.py get-app-name <manifest>

# 2) androguard 独立实现交叉验证（能发现"自洽但都错"）
python3 scripts/uncheck/tests/test-axml.py <manifest>

# 3) 装机后看系统是否识别 —— 唯一权威判据
adb shell "dumpsys package <pkg> | grep -oE 'ApplicationInfo\{[^}]*\}'"
#   能看到 className=<我们的类> 才算真的生效
```

### 2.3 载荷类是静态的，配置在 JSON 里

```
payload/*.dex              不含任何目标相关数据（可入 git / 可下载 / 可缓存）
assets/nc_sigfix/sigfix.json  唯一的目标相关数据：
                              {"cert": "<原证书 DER 的 Base64>", "originalApp": "com.x.Y"}
```

为什么不做「烘焙进 dex」：证书长度随 keystore 变（888~1152 字符），
改 dex 字符串池要重建；且每换一个目标 App 就要重编 dex。

### 2.4 每一步都必须兜住异常

`install()` / `attachBaseContext()` 里**严禁往上抛**。
目标 App 千奇百怪，我们的假设随时会错；崩了就等于这个模块不可用。

MT 的实现在简盒 v2.1.2 上就是栽在这：`IllegalAccessException`（改 static final
被拒）→ 抛 `RuntimeException` → `ExceptionInInitializerError` → App 在
`makeApplicationInner` 阶段崩。我们遇到同一条异常只记日志。

### 2.5 载荷类禁止读静态字段

handler 会被 `handlerLoader` 重新加载成另一个 Class 副本，静态字段不共享。
数据一律经构造器传入。

## 3. 挂载点：为什么是 `android:name` 而不是注入 Activity

```
ContentProvider.onCreate       最早
Application.attachBaseContext  ← 我们挂这里（SigFixApp）
Application.onCreate
Activity.onCreate              ← 只挂这里会漏掉上面三种
```

`SigFixApp` 是**代理**不是替换：装完 hook 后反射创建**原来的** Application，
清零它的 `mBase` 再调它自己的 `attachBaseContext`，
最后替换 `ActivityThread.mInitialApplication`。原继承关系与全部初始化逻辑都保住。

**为什么不学 MT 改父类**：MT 把 `extends Application` 换成
`extends KillerApplication`，原类若继承 `TinkerApplication` / `MultiDexApplication`，
换父类等于删掉那些逻辑，App 起不来。

## 4. 能力边界（对用户必须如实告知）

| 校验读取途径 | 覆盖 |
|---|---|
| `getPackageInfo().signatures` / `.signingInfo` | ✅ |
| `getApkContentsSigners()` / `getSigningCertificateHistory()` | ✅ |
| `checkSignatures()` / `getPackageArchiveInfo()` | ✅ |
| App 自读 APK 文件算哈希 | ❌ 需文件系统重定向 |
| native 层（`.so`）校验 | ❌ 完全无效 |
| 上报服务端裁决 / Play Integrity | ❌ **无解** |

后两类是结构性无解，不是「还没做」。工具不会假装能处理。

**强度验证未做**：只测过 JMComic（Java 层 PMS 校验）与简盒（有自定义
Application）两个真实包。样本量不足以谈兼容性。

---

## 5. 与「hook 框架」的关系（另一个需求，别混）

本模块是**改数据**：让系统返回的数据变成我们要的。
**不能**拦截任意方法调用 —— 纯 Java 在 Android 17 上做不到
（YAHFA/Pine 都停在 Android 12）。

要做「运行时 hook 任意方法、看参数、改返回值」是另一个产品，
需要 native inline hook（ShadowHook，官方声明支持 Android 4.1–17，MIT 许可）。
技术上可行，但不是本次需求，未做。

## 6. 日常怎么用

**用 ApkForge（本地 App）**：

```
选 APK → 开始处理（约 3 秒，纯本地）→ 产物未签名 → 自己 apksigner → 装机
```

ApkForge 侧完整文档见 `../ApkForge/docs/去签名校验.md`（跨仓库，同级目录）。

**本目录两条用途**：

```bash
# 1) 本地调试（Termux，需要 java + apktool）
bash scripts/uncheck/uncheck.sh in.apk out.apk --uncheck

# 2) 云端（App 传配置走 workflow）
#    .github/workflows/uncheck.yml，input 名是 protect_config
#    （这是 jian_box → EdgeRelay → workflow 三方冻结的键名，不能改名）
```

## 7. 两边同步纪律

| 改什么 | 同步到 |
|---|---|
| `scripts/uncheck/payload/src/*.java` | 跑 `payload/build.sh` → 产物 `boot.dex` / `payload.dex` 发布到 json 仓库 |
| `scripts/uncheck/axml_edit.py` 的逻辑 | `ApkForge/core/axml/AxmlEditor.kt` 必须同步改（两份实现，同样两条红线） |
| 载荷版本 | json 仓库 `backend/uncheck/index.json` 的 version + sha256 |

**唯一真相源是 `payload/src/`**，ApkForge 只消费编译产物。
