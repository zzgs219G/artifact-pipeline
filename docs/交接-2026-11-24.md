## 2. 本轮修的三个真问题

### 2.1 【最严重】加固包多 dex 时必崩 SIGBUS（nox 仓库）

**现象**：加固包注入 `classes2.dex` 后启动即 SIGBUS，
`fault addr` 每次都是 `0x89bcef3231`，签名完全一致也照崩。

**根因**：`ncg_scan_maps_for_base_apk()`（nox 仓库 `../nox/scripts/so-guard/nc_guard_boot.c`）用
`strchr(line, '/')` 取路径，遇到 Android 12+ 的 dalvik 匿名映射行：

```
[anon:dalvik-classes.dex extracte...=/com.x.base.A==/base.apk]
                                    ↑ 第一个 '/' 在这里
```

取出 `/com.x.base.A==/base.apk]`（缺 `/data/app` 前缀 + 尾部 `]`）→
`open` 失败 → `k_so` 派生返 -12 → `.ncx` 不解密 → 执行密文 → SIGBUS。

**该行只在包内多个 dex 被 dalvik 映射时出现**，所以"去校验注入
classes2.dex"会让加固包必崩——这个关联极难一眼看出。

**修法**：抽出 `ncg_path_from_maps_line()`，四条判据（以 `/` 开头 /
以 `base.apk` 结尾 / 不含 `[]` / 调用方 `open` 成功）。
⚠️ 不能拒绝 `=`：Android 安装目录名常含 `==`（base64 风格），那是合法的。

**回归**：nox `test.sh` 新增 V0（8 用例，纯函数不需 APK）。
反向验证：改回 `strchr(line,'/')` → V0 立刻变红并复现真机错误路径。

### 2.2 签名校验只走 `open`，被一次 hook 全废

**现象**：去校验的 `proxy_open` 把 `open(base.apk)` 重定向到诱饵
`origin.apk`（内含官方证书）。真机日志铁证：

```
path 打印是 base.apk，但 fsize=5066408 对应 origin.apk
（真实 base.apk 是 10MB）
```

**根因**：`sig_check.c` 和 `sig_guard2.c` 两条线**都只用 `open()`** 读
APK。AGENTS.md 里"两条独立线"指派生公式/处置路径独立，**读 APK 是共用
单点**。

**修法**：`sig_collect_fp()` 改为 6 路交叉采集：

| # | 路线 | 抗 hook 原理 |
|---|---|---|
| 0 | `open` | ❌ 会被拦（**保留作诱饵探针**） |
| 1 | `openat` | 独立符号 |
| 2 | `openat64` | 又一个独立符号 |
| 3 | `sig_raw_syscall(__NR_openat)` | 内联 svc，不经 libc |
| 4 | 内联 `svc #0`（本函数体内） | 连 `syscall()` 都不经 |
| 5 | `/proc/self/fd/N` + `readlinkat` 直投 | 复用 ART 已开的 fd，不发起 open |

判定：**成功 ≥2 路且指纹不一致 → `return -2` fail-closed**。

### 2.3 云端 `resources.arsc` 未 4 字节对齐，装机被拒

**现象**：`Failed parse during installPackageLI: Targeting R+ requires
the resources.arsc ... aligned on a 4-byte boundary`

**根因链**：
1. `uncheck.yml` 只装 NDK，runner 上**没有 zipalign**
2. `run.py` 找不到 zipalign 只警告后继续
3. 数据复用把 origin header（57B）插在最前，整体平移 57 → mod4=1
4. `resources.arsc` 落在 mod4=3 → Android R+ 硬性检查拒绝

**修法**（三处）：
- `uncheck.yml` 改用 `android-actions/setup-android@v3`（**必须带
  `packages: 'build-tools;34.0.0'`**，不带会报 `Failed to find package 'tools'`）
- `run.py` 找不到 zipalign 改为**硬失败**，不产出装不上的包
- `zip-reuse.py` origin header 用 extra field 补齐到 4096

⚠️ **LFH 与 CD 的 extra 必须等长**，只写 LFH 时 `zipfile` 读 CD 得
`extra_len=0`，实际平移量不变（踩过，单测只看 LFH 会误判成功）。

## 5. 关键教训（别再踩）

### 5.1 `openat()` 会编译成 `__openat_2`

C 里写 `openat(AT_FDCWD, path, O_RDONLY)`，`_FORTIFY_SOURCE` 把它编成
**`__openat_2`**。只 hook `openat` 等于没挂。

**判据不是猜，是看导入表**：`nm -D -u libnc.so | grep open`

### 5.2 `syscall@plt` 会破坏 kill 链

`sig_check.c` 里若写 libc 的 `syscall(...)`，会把 `syscall@plt` 拉回产物
→ `test-so-lock.sh` 的 **T9 立刻变红**（T9 守"产物里不得有
abort/_exit/raise/syscall 四个 PLT 表项"）。

**必须用 `sig_raw_syscall()`（内联 svc）**。

### 5.3 armv7 的 `r7` 是保留寄存器

clang 拒绝 `register long r7 __asm__("r7")`，报
`error: write to reserved register 'R7'`。
必须在内联汇编里 `push {r7}` / `pop {r7}`——照抄 `env_check.c:env_raw_syscall`。

### 5.4 "哪一路是诱饵"按多数派判定

不能按"第一个成功的"。被劫持的往往正是最先成功的 `open()`，
以它为基准会把 5 路真货全标成"不一致"（实测踩过）。

### 5.5 CI 的裸 `clang` 是 NDK 交叉编译器

判据用**可执行性**，不是编译器名字。用 `scripts/lib/host-cc.sh` 的
`nc_pick_host_cc`。

### 5.6 `make-sig-log.py` 的参数顺序

`make-sig-log.py <源.c> [...] <输出.h>`——**最后一个参数是输出文件**。
传错会把源文件覆盖成头文件内容（我犯过，`sig_guard2.c` 被覆盖，
用 `git checkout` 恢复）。

正确调用（照抄 `protect.sh:676`）：

```bash
python3 scripts/guard/log/make-sig-log.py \
  scripts/guard/src/sig_check.c \
  scripts/guard/src/env_check.c \
  scripts/guard/src/env_probes.c \
  scripts/guard/src/sig_guard2.c \
  <输出路径>/sig_log_data.h
```
