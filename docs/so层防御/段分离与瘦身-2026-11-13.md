## 2. 体积瘦身（已上线，净收益最大的一项）

### 2.1 做了什么

**① 顶掉 libc++abi 的 demangler**

新增 `scripts/guard/src/nc_demangle_stub.c`，用同名强符号覆盖 `__cxa_demangle`。

因果链（照抄 dpt-shell 2026-11-10 的结论）：

```
APP_STL := c++_static
  → libc++abi.a 的 cxa_default_handlers.cpp.o（导出 __cxa_terminate_handler）
  → 它引用 __cxa_demangle
  → cxa_demangle.cpp.o（606 个符号，.text 里近 100KB）整块被拉进 so
```

**② 关异常/RTTI**

`lib-ndk.sh` 的 `APP_CPPFLAGS` 加 `-fno-exceptions -fno-rtti -fno-unwind-tables`。

### 2.2 效果

```
libnc.so:  662,712 → 528,536 B   (-166KB, -25%)
APK:       6,235,479 → 5,263,547 B  (-972KB)
  .text     307,964 → 207,788      (-100,176)
  .rela.dyn  33,312 →  4,320       (-28,992)   ← RTTI/异常表
  .data.rel.ro 12,104 → 1,240      (-10,864)   ← vtable
```

### 2.3 ⚠️ 试过但**失败**的：`APP_STL := c++_shared`

`libnc.so` 确实降到 454,328 B（-42KB），**但 NDK 会把 `libc++_shared.so`
整个复制进 APK 的 `lib/<abi>/`（1,794,776 B = 1.7MB）**。

净效果：APK 反而大 1.75MB。**已回滚，并在 `lib-ndk.sh` 注释里记下实测数据防止重试。**

### 2.4 代价（如实）

- 崩溃提示从 `std::bad_alloc` 变成 `St9bad_alloc`（只影响开发者可读性）
- libnc.so 内不能再写 `try/catch` / `typeid().name()`
  （现在没有：sig_check/env_check/nc_link 全是 C；dex2c 用 `EX_LandingPad` +
  显式 `goto` 分发，不依赖 `.eh_frame`）
- **⚠️ 将来若加 try/catch，必须删掉 stub 文件和那两个 flag**

## 4. 段分离：做到了什么、卡在哪

### 4.1 目标

用户想要：**一眼看出 VMP 数据在哪、有多大**，进而对它做锁箱加密。

### 4.2 已经做到的（nox12/nox13 真机验证）

**`.ncr` 段成功分离，`readelf` 可见：**

```
[29] .ncr  PROGBITS  ...  146,904 B  WA
```

**一个命令就看到 VMP 数据在哪、多大。**

### 4.3 加密失败的真因（这次找到了）

**关键实测：`.ncr` 里有 83 个 `R_AARCH64_RELATIVE` 重定位，全部集中在
`0xc350 ~ 0x23548`（descriptor_table + native_call_table 区间），几乎每 8
字节一个。**

```
offset  0xc350, 0xc358, 0xc360, ... （80 个间隔都是 8）
```

**这些位置在文件里是占位符，`dlopen` 时由动态链接器填入真实地址。**

**如果整段加密，解锁时把解密结果写回 → 覆盖掉链接器填好的指针 → 垃圾指针
→ 解释器跳错地址 → 真机 SIGILL。**

这就是"加密就崩、不加密不崩"的机制。

### 4.4 之前的误判（记下来防止重犯）

| 我的判断 | 实际 |
|---|---|
| "段名 `.ncr` 导致崩溃" | 部分对：nox9 崩是因为它加密了（含指针），不是段名 |
| "删掉 set_section 才正常" | **错**：nox10 那次构建实际用的是 nox9 的 bundle（CI 缓存/URL 没换），结论无效 |
| "Amice 的 set_section 有缺陷" | 不成立：nox12 用 set_section 且真机能跑 |

### 4.5 `.ncr` 内部结构（供后续加密参考）

```
0x00000 ~ 0xc350    字节码 + const_pool + metadata   ← 纯数据，可加密
0xc350 ~ 0x23548    descriptor_table + native_table  ← 含 83 个指针，不能加密
0x23548 ~ 0x23dd8   尾部
```

## 5. nox14（待验证的新方案）

### 5.1 思路

按「是否含指针」把 5 类 global 拆成两类段：

| 段 | 装什么 | 段属性 | 可加密 |
|---|---|---|---|
| `.ncr` | 字节码 / const_pool / metadata | 待验 | ✅ |
| `.ncd` | descriptor_table / native_call_table | 待验 | ❌ 必须明文 |

### 5.2 同时做的：段名不再硬编码

```bash
AMICE_VM_DATA_SECTION=".ncr"   # 纯数据段，默认 .ncr
AMICE_VM_PTR_SECTION=".ncd"    # 指针段，默认 .ncd
```

值非法（非 `.` 开头）时回退默认并告警。

**这样使用者换段名不用改源码**（之前是 `const VM_DATA_SECTION = ".rodata.ncr"` 硬编码，
用户提出质疑，已改）。

### 5.3 验证顺序（重要）

**先不加密，只验证「拆成两个段」本身安全**，再试加密。不要一步到位。

## 6. 踩过的坑（这次新增的）

### 6.1 CI 换 bundle 版本要改三处

`.github/workflows/protect-modules.yml` 里有 **3 处** `key:` + `URL=`；
`nox/.github/workflows/release.yml` 里 **2 处**。

**我曾漏改 `protect-modules.yml`，导致连续 3 次 bundle 换代都没生效，白白
浪费了 3 次构建和错误结论。**

```bash
# 换版前先确认
grep -n 'v0.1.6-nox' .github/workflows/protect-modules.yml ../nox/.github/workflows/release.yml
```

### 6.2 段名抽取的正则要允许数字

`so-section-lock.py` 的 `_load_layout_contract()` 用
`#define\s+(NC_SEC_[A-Z_]+)` 抽段名 —— **匹配不到 `NC_SEC_VMP2`（带数字 2）**。

症状：`_LAYOUT` 缺键 → `lock()` 抛 `KeyError` → 一级锁箱整体失败。

已改为 `[A-Z0-9_]+`。

### 6.3 可选段的段序必须动态决定

`.nct` 是可选段（没开第二套 VMP 的产物没有它）。写死段序会导致：

```
有 .nct： 0=.nct  1=.ncx   2=.ncxr
无 .nct： 0=.ncx  1=.ncxr           ← 写死索引时把 k_nct 用在 .ncx 上
```

症状：解出乱码 → `test.sh` 的 V6 报"正常包也会挂"。

修法：引入 `has_nct` 标志，`kso_idx`/`ksor_idx` 动态计算。

### 6.4 跨语言 label 长度必须对齐

`NCGL_INSN` 曾写成 11，而 `"nc-insn-v1"` 实际长度是 **10**。

C 侧按 11 读表 → 还原出 `"nc-insn-v1\x??"` → HKDF info 错 → `k_nct` 错。

**已加 `_Static_assert(sizeof("nc-insn-v1") - 1 == NCGL_INSN, ...)` 钉死。**

**教训：Python 侧能解只证明文件加密正确，不证明 C 侧能解。两边要分别验。**

### 6.5 `adb install` 显示 Success 不等于装上了

未签名的包会被系统静默拒绝，但仍打印 `Success`。

**核对方法**：

```bash
adb shell "unzip -l $(adb shell pm path com.xixin.box | sed 's/package://') | grep libnc.so"
# 对比本地 so 的大小
```

### 6.6 `trigger_build.py` 默认不签名

```bash
python3 scripts/trigger_build.py app.apk --sigcheck --dex2c        # 未签名
python3 scripts/trigger_build.py app.apk --sigcheck --dex2c --sign # 已签名
```

`--all` 才默认带签名。产物会自动下载到 `/sdcard/Download/`。
