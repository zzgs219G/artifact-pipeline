## 0. 两层防护的命名（先看这个，不会再混）

| 你看到的词 | 是什么 | 谁控制 | 体积 |
|---|---|---|---|
| **锁箱** | `.ncx` 六段加密：磁盘上是密文，运行期自己解锁。**一直在，不用开** | nox 设施（tools/nox.zip），构建自动 | ~几 KB 槽段 |
| **nox-obf / nox-VMP** | **nox 解密链本身**被 VMP 化 + 混淆（烧进 libnox.a，发版时决定） | nox 发版 tag 的 `-obf` 后缀（CI 自动）；本地直打须设 AMICE_BUNDLE | .a 508KB（VMP 占 95KB 字节码+142KB 解释器） |
| **--vmp（消费方层）** | **签名校验判定逻辑**被虚拟化（sig_check/guard2 的判定点） | `--vmp` 参数（默认不开） | so +200KB~470KB |

**一句话**：锁箱+nox 层 VMP 你天然就有；`--vmp` 加的是"签名校验判定逻辑"的虚拟化。
88.66K 事故（2026-11-24）就是"以为有 nox-VMP 实际发版时丢了"——现在 T34 断言+登记表会拦。

## 4. 排障三板斧（真机闪退时）

```bash
adb shell "touch /storage/emulated/0/xixin_debug"    # 开日志哨兵
adb shell "cat /storage/emulated/0/Android/data/<包名>/files/ncguard_log.md"   # 锁箱报告
adb shell "cat /storage/emulated/0/Android/data/<包名>/files/sigcheck_log.txt" # 签名校验明细
adb logcat -d | grep 防线   # 死亡归因：防线0=锁箱 / 防线1=sig_check / 防线2=sig_guard2
```

### 4.1 装了包但日志文件不出现？

**目录比日志逻辑晚出现**，这是 Android 的存储模型决定的，不是 bug：

```
/storage/emulated/0/Android/data/<包名>/files/
    ↑ 这个目录由【第一次文件写入】隐式创建
    ↑ 而 <包名>/ 那一层 App 无权自建
      （父目录 Android/data 是 drwxrws--x，其他用户只能进不能写）
```

所以 **`files/` 目录出现之前写的日志写不进文件**。两个模块都已处理：

| 模块 | 处理方式 |
|---|---|
| 签名校验 / 环境检测（`nc_log`） | 写不了就打 logcat 并标 `[no-file]`；同时起后台线程 2 秒后重试一次 |
| 锁箱报告（`ncg_report_flush`） | `fopen` 失败时起后台线程 2 秒后重写一次 |

**首次启动通常 2 秒内就绪**（实测最快 2.13 秒）。若等了十几秒还没有：

```bash
adb logcat -d | grep "nc_log:"      # 看是"目录没建"还是"哨兵没开"
adb logcat -d | grep "\[no-file\]" # 这些行只进了 logcat，没进文件
```

⚠️ 极端情况（实测最坏 104 秒）2 秒重试会错过 —— 那时文件里没有，
但 **logcat 里一条不少**（`adb logcat -d | grep "nc: "`）。

闪退归因速查：
| logcat 显示 | 含义 | 修法方向 |
|---|---|---|
| `【防线0·锁箱】解锁 rc=-11: MAC 校验失败` | 产物被篡改或**换证书重签** | 用原证书签 |
| `rc=-12: 定位不到自身 APK` | 抽壳/改包结构 | 查包结构 |
| `rc=-13: 证书读不出` | Signing Block 被破坏 | 查签名工具 |
| `rc=-14: 包名对不上` | applicationId 改名/双开 | 恢复包名 |
| `【防线1·sig_check】多路证书指纹不一致` | APK 读取被劫持（去校验工具） | 预期对抗行为 |
| `【防线2·sig_guard2】… → SIGKILL` | 第二线独立确认不一致 | 同上 |
